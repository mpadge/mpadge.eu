# mpadge.eu

Source for [personal blog](https://mpadge.eu). See [this post](https://mpadge.eu/blog/making-this-site.html) for details.

## atproto workflow

Everything on the site (blog posts and notes) is also published as
[`site.standard`](https://standard.site) records on my [AT Protocol
PDS](https://atproto.at/uri/at://did:plc:yrzruxieyscusyvcz6t5xlvh), and each
page can have a comments section fed by Mastodon and/or Bluesky.

`make help` prints a short version of this section.

### What gets published

`make publish` writes these records to the PDS of `mpadge.eu` (default
`https://tngl.sh`; override with `ATPROTO_PDS`):

| Record | rkey |
| --- | --- |
| `site.standard.publication` | `mpadge` |
| `site.standard.publication` | `notes` |
| `site.standard.document` | blog post slug |
| `site.standard.document` | `note-<slug>` |

- Records use `putRecord` with fixed rkeys, so **re-running is idempotent**: it
  rewrites every record in place (and never deletes any). The `note-` prefix
  keeps note rkeys from ever colliding with blog slugs.
- Readers build a document's URL as *publication url + document path*. The notes
  publication url already ends in `/notes` (so that its `.well-known`
  verification is served under `/notes`), so note paths are relative to it:
  `/atproto.html`, not `/notes/atproto.html`, which readers would show as
  `/notes/notes/atproto.html`.
- The resulting AT-URIs are saved to `src/atproto.json`. The build reads that
  file to add `<link rel="site.standard.document">` to each page and to write
  the `.well-known/site.standard.publication` verification files. **It must be
  current before the site is built**, so never build or deploy before running
  `make publish`.
- The account (`mpadge.eu`) is hard-coded in the makefile. The app password
  comes from `$ATPROTO_APP_PASSWORD` if set, otherwise from
  `pass show atproto/app-password` (first line). `make publish` fails if
  neither gives a password.

### Workflow for a new post or note

```bash
make blog      # render the post ('make render' for $(BLOG)); notes are plain .md
make update    # local only: blog and notes data (src/data/*.yml), RSS, llms.txt
make publish   # atproto records + src/atproto.json
git commit     # include src/atproto.json and everything updated above
git push       # the Codeberg webhook builds and deploys the site
```

For a manual deploy instead of the webhook: `make build`, then `make deploy`.
`make update` never touches atproto. `make publish` only touches atproto and
`src/atproto.json`, plus the front matter of an item it announces (see below).

**Slugs.** A slug is the file name without the leading `YYYY-MM-DD-` and the
`.md`: `2026-11-10-git-push.md` is `git-push`. For blog posts it must equal the
`link:` in the post's front matter (minus `.html`), which it does for all
existing posts. Notes have no `link:`; their slug comes only from the file name.

**Generated data.** `src/data/blog.yml` and `blogshort.yml` are generated by
`tools/blog/update_main.R` from each post's front matter. `src/data/notes.yml`
(full list, used by `src/pages/notes/index.html`) and `notesshort.yml` (home
page) are generated from the note files, by `make update` and by every build.
Edit the posts and notes, not the generated YAML.

### Comments (Mastodon and Bluesky)

A post or note gets a comments section if its front matter has `mastodon:`
and/or `bluesky:` set to the URL of a post there. `src/assets/js/comments.js`
fetches the replies in the visitor's browser from the services' public APIs (no
login, no server component) and shows them in one list: top-level replies in
time order, each followed by its own thread, with a badge per source. Either
field, both, or neither work; a source that fails to load is reported on the
page. The privacy page says so.

### Announcing on Bluesky

The Bluesky post is the comment thread, so each post or note needs one. Two
ways to get it:

**Let `make publish` create it.** Add the slug of the item (blog post or note):

```bash
make publish POST=git-push     # a blog post
make publish NOTE=atproto      # a note
```

- This creates a **public** Bluesky post as `mpadge.eu`. It shows the exact
  text first and asks `[y/N]`. Anything but `y` cancels. The records are
  published before the prompt, whatever the answer.
- The text is `<title>`, a blank line, then `<description>`, and must fit
  Bluesky's 300 characters (graphemes). This is checked **before anything is
  written to the PDS**; too long is an error with the breakdown. Most blog
  descriptions are too long: give your own text with
  `make publish POST=git-push TEXT="..."` (also checked against the limit; it
  needs exactly one of `POST` / `NOTE`; quotes in it are safe).
- The link card has the page's title and description and no thumbnail.
- It then records the post's URL as `bluesky:` in the item's front matter (and
  in `src/data/blog.yml` for blog posts, so no `make update` is needed first).
  Commit those files.
- It is **skipped for anything that already has a `bluesky:` link**, so
  re-running it never posts twice. To replace a link, edit the front matter.
- Preview the text without posting or writing anything:
  `node tools/atproto/publish.mjs --announce=<slug>` (or `--announce-note=`).

A plain `make publish` ends by listing recent items (last 30 days) that still
have no `bluesky:` link, with the command to announce each.

**Post it yourself, then link it.** If you posted on Bluesky by hand, run:

```bash
make bluesky                                   # find and link them automatically
make bluesky POST=git-push BSKY=https://bsky.app/profile/mpadge.eu/post/<rkey>
```

The automatic mode reads your last 500 public posts (no login) and links any
that contain a link to a post or note without `bluesky:` (a link card or a link
in the text; reposts and other accounts are ignored; if several match, the
earliest is used). It only edits local files; commit them. The explicit form
links one post and refuses to overwrite an existing link.

### Semble cards

`make publish` also files a `network.cosmik.card` for every blog post and note
(visible at <https://semble.so/profile/mpadge.eu>), in the Semble collections
"mpadge blog entries" and "mpadge note entries" (create these by hand in Semble;
they are looked up by name). A URL that already has a card is reused, and an
existing collection link is left alone, so re-running is idempotent. Cards are
not updated after creation; edit them in Semble.

### Preview cards

The social preview (`og:` and `twitter:` tags) of a blog post or note is its
**first landscape image**, if it has one (portrait images are skipped, because
link cards crop to landscape; only existing files under `src/` with a
root-absolute path count). Otherwise the page gets a **text card**: no image
tags and `twitter:card=summary`, so services build the card from the title and
description. The site-wide image (`mpadge-og.jpg`) is only used for pages that
are not posts or notes, such as the indexes. The choice is made in
`tools/site/ogImage.js`; `textcard: true` in a page's front matter (set by the
build) switches off the default image in `src/layouts/default.html`.

### Pre-commit check

Enable once per clone with `make hooks` (it sets `core.hooksPath` to
`.githooks`). When anything in `src/data/` is staged, the hook runs
`tools/atproto/check.mjs` (also `make check`), which fails if a blog post or
note has no record in `src/atproto.json`, if the file contains dry-run
placeholder DIDs, or if it has unstaged changes. In other words: it stops a
commit that would ship a page whose `make publish` was forgotten. Commits that
do not touch `src/data/` are never blocked. It only guards this machine, not
the webhook deploy.
